## 🚀 快速开始

### 方式一：双击一键启动脚本（推荐）

双击 `启动外贸英语网站.bat` —— 自动检测 Python/Node、**先探测端口再启动服务器、确认端口可连后才打开浏览器**，访问 **`http://localhost:8000`**。
关闭弹出的启动窗口即自动停止服务器。此方式下语音（发音/评测/语音输入）功能完整可用。

> **端口的"绝不自动换"原则（重要）**：`localStorage` 按 **origin（协议+主机+端口）** 隔离，而你的词卡状态、打卡、错题、逐句笔记全都在里面。**换端口不是换个数字，而是让这些进度"看起来丢了"**（其实还在旧 origin 下）。所以：
> - 默认就是 **8000 + `localhost`**，与历史完全一致 → **老用户零迁移**；
> - **8000 被占用时脚本不会自作主张换端口**，而是停下让**你**选：① 关掉占用它的程序再启动（推荐，进度不受影响）；② 明确同意换端口继续（会打印 origin 变更与迁移办法）；
> - 非交互场景（脚本 / CI / `-NoBrowser`）**一律默认"停下"**，绝不静默改 origin；
> - 想省掉每次询问，可以显式放行：`启动外贸英语网站.bat -AllowPortChange`。
>
> **内部探活走 `127.0.0.1`，地址栏走 `localhost`**（两者分开是刻意的）：本机 `localhost` 先解析到 IPv6 `::1`，那次连接要卡约 2.3 秒才回落（实测 2.3s vs 1.1s），探活若用它加短超时会**每次都超时**，表现为"服务器明明起来了、浏览器就是不弹"。探 `127.0.0.1` 可绕开 DNS/IPv6/HTTP/系统代理（本机还装有 WinHTTP 代理且 Bypass List 为空）。

### 方式二：直接双击打开（最快，仅浏览）

双击 `index.html`。适合浏览课程、搜索、背单词、做测验；**注意**：`file://` 协议下 Chrome 会禁用语音识别/TTS/录音，听说功能不可用。

### 方式三：手动本地服务器（听说功能最完整）★推荐

在 `外贸英语` 目录打开 PowerShell / CMD，运行：

```bash
python -m http.server 8000
```

然后浏览器访问：<http://localhost:8000>（手动起服务器时端口自己定，注意**换端口=换 origin**，旧进度不会跟过去，见上方说明）

| 🔄 **中断回归协议**（`js/today.js`） | 站点一直有连续打卡与热力图，但**「中断之后怎么办」完全没有设计**——而「停了两周」恰恰是最常见的真实情况，也是用户彻底放弃的时点。做法：从 `progress.coach.lastDate` 算出**间隔天数**（< 2 天不打扰），停了 ≥2 天时在「今日」顶部给**四行事实**：① 只记事实（不作人格判断）；② 24 小时内**只做这一件**（一键切到既有精简模式 = 前两步约 9 分钟）；③ **这次明确不补做什么**——不补那 N 天的作业、不熬夜还债（连续打卡会从今天重算，但已掌握的词与 FSRS 排期**不会清零**）；④ 同一个阻力连续出现三次就**改条件**（时间盒/任务大小/环境），而不是再逼自己一次。刻意不像"催打卡"那样追责 |

> **难度标定的科学性与局限（重要）**：本站词级难度使用**真正的 CEFR 分级**——来自开放的 [CEFR-J 英语词汇画像](https://github.com/openlanguageprofiles/olp-en-cefrj)（A1–B2）与 Octanove C1–C2 扩展（构建期读取 `tools/cefr/`），比旧的"音节+词长"代理更贴近真实学习难度。
> - **词级**：A1/A2=**易**、B1=**中**、B2/C1/C2=**难**；未收录（多为行业/复合术语或低频）按词长+音节兜底并标「专」为**行业术语**（与难度正交）。
> - **单元级**：给出**平均 CEFR 档 / 平均句长 / Flesch 可读性 / 专业词占比**供参考，其中**难度档（基础/进阶/拔高）只衡量语言复杂度**——由 0.5×平均 CEFR 档 + 0.3×每词音节数 + 0.2×平均词长（三者取本站语料内分位）合成后，按单元间相对位置切档；**平均句长、Flesch 可读性与专业词占比不参与该合成分**。因此**术语密集型单元（U7 物流 / U13 海运）可能落在「基础」档**——那说的是措辞好读，不是说业务好做。
> - **局限**：本站多为专业复合词，CEFR 直接命中率有限（其余靠兜底）；单元序用于**站内相对选择**，不声称与外部量表完全对齐。为让"按水平开始"更贴合个人，首页与每个单元都有 **🎯 水平自测**（`#/placement`，按难度梯度采样词义题）推荐起点单元与阶段。

### 🎙️ 语音能力（VPN / PC 代理场景最佳）

你有常开 VPN（国内直连、国外走代理），这是**使用浏览器在线语音的最佳场景**：

- **发音（三音源）**：
  - **浏览器语音（默认）**：系统自动优先选择高音质在线神经网络人声。**最省事的是用 Microsoft Edge**：在 Edge 设置 → 语音 → 首选发音设为 Online (Natural)，即可获得接近真人的微软神经人声，免费、无需 Key。
  - **Azure 语音（推荐给固定用 Chrome 的用户）**：在设置里选「Azure 语音」并填入订阅 **Key + Region**（在 Azure 门户创建 Speech 资源即可）。质量与 Google 在线语音同档甚至更自然，且为正规接口、浏览器可直接跨域调用；免费额度够日常练习。失败自动回退浏览器语音。
  - **Google 在线**：第三方免费端点，常被 Google 封禁而失效，已标为“不稳定”，不再推荐。
- **浏览器在线语音识别**（跟读评测 🎯、AI 陪练 🎤）：依赖 Google。你的 VPN 让 Chrome 可访问时即自动生效，评测自动重试网络抖动。
- 若某次识别报"网络错误"：多为 Chrome 未走代理 → **Chrome 设置 → 系统 → 开启「使用系统代理」**，或让 VPN 全局接管；也可先点「🔍 诊断语音」确认 Google 是否可达。
- **兜底**：Android 无法在线识别时，可聚焦输入框按 <kbd>Win</kbd>+<kbd>H</kbd> 用系统听写，或以「逐句跟读 + ● 录音对比 + 听写训练」为主练习听说。

> 评测算法会**逐词分级**：精确命中全分、近似/错拼（如 forward≈fourd）给部分分、漏读标红——帮助你精准定位哪个音没发对。

### 🗣️ AI 口语陪练

1. 点击顶部导航「**AI 陪练**」；
2. 在「模型设置」中选择服务商（推荐 **DeepSeek**，支持浏览器跨域），填入 **Base URL**、**模型名**、**API Key**（如 `https://api.deepseek.com` / `deepseek-chat` / 你的 `sk-...`），点「保存设置」；
3. **教练规则（推荐）**：默认已套用教练式预设——先交流、不逐句打断；每 3 轮集中复盘 2 个最明显的错误、给出 1 个更自然的表达和 1 个值得重复的句子；卡住时只给关键词提示，不替你说完整答案；结束给出 10 分制评分与下次重点。可在「🎯 教练规则」里改「纠错节奏 / 语速 / 等我说完再回应」，「⤵ 一键教练预设」随时一键还原。
4. 从「**选择一个场景开始对练**」点一个外贸真实场景（展会接待、询盘报价、商务谈判、电话沟通、售后客诉、视频会议、物流、机场/酒店）填入输入框并发送，再开始全英文角色扮演；也可直接用英文或中文开口。
5. 对话中导师会：
   - 全程用英文交流，你说中文会先翻译成英文再接话；
   - 按你设定的「纠错节奏」纠错（可每 3 轮复盘，或立刻纠正，或全程不纠正统一总结）；
   - 遇到新词按「【新词: 单词 | 释义 | 例句】」格式标注，**自动收录**到页面下方的学习词汇表；
   - 结束给出 **10 分制评分 + 下次练习重点**；
6. 每条回复可点「🔊 朗读」「🌐 翻译」「➕ 今日错题」；点回复里的英文单词可手动加入词表；**语音对话闭环**：点 🎤 用浏览器在线识别把你说的英文填入输入框 → Enter 发送（VPN 场景下效果好）；不生效时用系统听写（Win+H）。
7. **今日错题 · 下次复习**：聊完点「🪄 让 AI 提炼本场错句」把 2 个明显错误 + 1 个更自然表达加入清单，或手动把 AI 回复加入；**第二天先复述它们**（🔊 朗读 → 跟读），掌握了点 ✓ 移除。口语不是靠收藏资料增长，而是靠把说不顺的句子重新说顺。
8. **🎯 四维评分本场对话**：场景对练中想评测自己说得好不好，点对话区右上「🎯 四维评分本场对话」，系统会把你本场所有英文应答带到「四维口语实战」中最贴近的场景，再补一步「跟读参考句」即可得到完整的四维分（行业术语发音 / 语调流利度 / 商务应答准确性 / 表达逻辑性）。

> ⚠️ API Key 仅保存在本浏览器 localStorage，不会上传到本站任何服务器，但请勿在公共电脑使用。
> ⚠️ OpenAI 官方接口可能被浏览器跨域（CORS）策略拦截，如报错请改用 DeepSeek 或自定义 CORS 兼容端点。

### 🎯 跟读评测的准确性说明

评测采用「浏览器语音识别 + 逐词对齐」，**识别来源三选一**：

- **浏览器在线**（默认）：Chrome/Edge，依赖 Google（你有 VPN 时走代理）。**分级评分**：精确命中（全分）/ 近似·错拼（部分分，标注 ≈你读的音，如 forward≈fourd）/ 漏读·多读（标红）。
- **本地离线 vosk-browser**：发音设置勾选「优先本地识别」后，跟读评测改用 Kaldi wasm（跨 Safari/Firefox、可断网）。需把解压后的 `models/vosk-model-small-en-us-0.15/` 放到站点根目录、`vosk.js` 放 `js/vendor/`（运行 `tools/fetch-vosk-model.ps1` 一次）；未就绪时自动回退浏览器在线识别。
- **Azure 音素级**（🔎 按钮）：同 Key 打分，见「四维口语实战」。

给出加权准确率 + 精确率，并附针对性练习建议（慢速分音节跟读等）。为获得更高准确度：

- 使用 **Chrome / Edge**（语音识别依赖 Google）。你有 VPN，识别自动走代理；若某次报错，可先点「🔍 诊断语音」确认 Google 可达，或到 Chrome 设置 → 系统 → 开启「使用系统代理」
- 保持环境安静、靠近麦克风、语速放慢；识别失败会自动重试
- 首次使用需允许麦克风权限；误点拒绝时点地址栏左侧麦克风图标改为「允许」后刷新
- 评测分数受口音和识别模型影响，作为**练习参考**而非绝对标准；无法在线识别时可用「录音回放对比」+「听写训练」练习听说

### 🔧 工程化：测试 / 审计 / 单一数据源 / CI（零依赖）

纯静态运行时零依赖；下面这几条只是**开发期**的校验命令，靠 Node 内置模块跑，无需 `npm install`（Node ≥16）：

| 命令 | 作用 |
|------|------|
| `npm test`（= `node tools/test-all.js`） | 跑**门禁**：**启动完整性 + 多页渲染**（按 index.html 真实顺序执行全部脚本，并在沙箱里真实渲染首页/教练手册/口语测评/今日/课程/写作/听说 7 页做断言，任何加载期抛错或渲染出错即失败）、FSRS 对齐官方、FSRS 四档行为、句块切分、字幕解析、进度 schema 迁移、句型克隆、**写作二稿闭环 + AI 留痕/独立复测**、**说我想说**、**音素课与高危音**、**今日 + 中断回归/复测提醒**、**水平自测 v2 诊断层**、**首页 P1**、**场景急救**、**静态资源接线**，任一失败即中断；并重算数字/IPA 报告 |
| `npm run audit` | 单独重算 report-count.json 与 report-ipa.csv（不用门禁） |
| `npm run check:singlesource` | 小程序 `utils/data.js` 与网页版是否一致；不一致即 fail（防单一数据源漂移） |
| `npm run sync:miniprogram` | 从 `js/data*.js` 重新生成小程序版数据（改网页版内容后运行一次） |

`.github/workflows/ci.yml` 会在每次 push/PR 跑 `npm test` + `check:singlesource`，改代码即校验，防止"文档/数字/算法漂移"再次发生（历史上曾出现 SM-2 误写与词汇数前后矛盾；现在**正文数字也由 `tools/test-doc-numbers.js` 与数据对账**，不再只靠报告类脚本兜底）。

**浏览器内冒烟页（P7 新增，手工跑）**：`tools/smoke-subtitle.html` 用**真实 DOM**驱动字幕模块的点击路径（切四档 → 检查露/藏什么 → 点 👁 看回译对照 → 切口音 → 单语字幕回落；P8 追加：A-B 开启/关闭/慢速与「点笔记控件不得触发播放」的行为断言），页面底部直接打印 `pass=/fail=` 与逐条日志。它**不接入 `npm test`**（零依赖原则下不引 jsdom），因为纯逻辑已由 `tools/test-subtitle.js` 与 `tools/test-subtitle-ab.js` 守门，这里补的是"点了到底有没有反应"。
跑法：在 `外贸英语/` 目录起本地服务器后打开 `http://localhost:<启动器打印的端口>/tools/smoke-subtitle.html`（默认 **8000**；**被占用时启动器会自动顺延到 8001/8002…，以它打印的 URL 为准**）。
⚠️ **受限沙箱下无头浏览器会失败**（`mojo platform_channel ... 拒绝访问 (0x5)`——Chrome 多进程 IPC 需要命名管道），这一点与 `tools/build-assets.ps1` 的位图渲染同一个原因，**在普通终端里跑即可**。

**加载顺序耦合的加固（P1）**：`index.html` 按顺序引入 20 多个 `<script>`，靠全局共享。为防"某文件被删/顺序错/加载失败"导致**静默坏掉**，`app.js` 启动时有**完整性校验**：逐一检查课程数据(U1–U16)、易错点、助记、难度、Player/Flashcards/Quiz/Listen/Eval4/Tutor/SOP/Export/LocalASR/Sources/Subtitle 等是否就绪，缺失即在控制台报错并列出缺哪个。另外修复了**两个因 FTE_DATA 用 `const`（非 `window` 属性）导致的静默 bug**：`export.js` 的词表 CSV 导出此前恒为空、`subtitle.js` 的"点词查意"查不到词——均已改回直接引用全局 `FTE_DATA`。

## 📌 使用提示

- **发音**：右上角 ⚙ 可切换「在线高音质」音源（发音更标准自然，需联网；网络异常自动回退浏览器语音），也可手动选择发音人；首次使用浏览器语音时可能提示下载语音包。
- **录音/评测**：浏览器会弹出麦克风权限请求，请允许；请用「方式一 / 方式三」通过本地服务器访问（`file://` 下语音受限）。智能评测建议 Chrome / Edge。
- **进度**：进度存储在浏览器 localStorage 中，清空浏览器数据会丢失进度。
- **兼容性**：推荐 Chrome / Edge / Firefox 最新版（TTS、录音、语音识别需要较新浏览器）。

### B. 评分诚实化与「完成≠证据」（Phase 1）

| 项 | 改动 | 落点 |
|---|---|---|
| 音素诊断 | 此前 `text \|\| scene.ref` —— **识别失败时拿参考句冒充识别结果**，于是任何人任何一次都得到「✅ 音素一致率 100%」。现在无识别结果就**明确拒绝诊断**并说明原因，不给任何一致率 | `js/eval4.js` |

### 8-4 顺带修掉：启动器「先开浏览器、再起服务器」导致看错网站

现象：双击 `启动外贸英语网站.bat` 后，浏览器里出现的是**另一个应用**（本机实测：本地记忆管理应用「记忆核心 · Memory Eternal」的页面，占着 `127.0.0.1:8000`），看不到学习界面。

根因（原脚本的真实缺陷，不是端口巧合）：启动脚本的顺序是 **先 `Start-Process $url` 打开浏览器，再 `bind` 8000**。所以只要 8000 有任何东西占着，python 绑定就失败（`WinError 10013`，因为对方用了 `SO_EXCLUSIVEADDRUSE`，所以不是常见的 10048），而浏览器**已经打开了** → 你看到的就是占用 8000 的那个程序。

修复后的顺序：**先探测端口（直接尝试 bind，一次识别"被占用 / 被独占 / 落在系统保留段"三种情况）→ 选一个真能绑的（顺延，最多 20 个）→ 起服务器 → 探活真的返回 200 之后才打开浏览器**；若 20 个端口全不可用，则**不开浏览器**直接给出占用者查询命令。新增 `-NoBrowser` 开关（仅起服务器）用于自动化验证。

**默认端口先改为 8088、随后又回到 8000，最终定为「8000 + 绝不自动换端口」**：8088 是为了避开那个反复出现的占用者，但改端口会**连带改掉 origin**，导致老用户的 `localStorage` 进度"看起来丢了"——所以最终策略是**默认 8000 不变；被占用时停下并让用户明确选择**（关掉占用者再启动 / 或同意换端口），非交互场景一律默认停下，另提供 `-AllowPortChange` 显式放行、`-Port <n>` 显式指定端口，`.bat` 已加 `%*` 转发参数。

⚠️ **该脚本必须保持纯 ASCII**：`.bat` 用 `powershell.exe`（Windows PowerShell 5.1）执行，而 5.1 对**无 BOM** 的 `.ps1` 按系统 ANSI 代码页（中文系统为 GBK）解码——写进中文提示会变成乱码**并直接破坏语法**（本轮实测：4 处语法错误，启动器会当场坏掉）。所以提示文案沿用英文。仓库里其它含中文的 `.ps1`（如 `tools/fetch-vosk-model.ps1`）同样存在"输出乱码"的轻微问题，可选手工加 UTF-8 BOM 解决。

**实测验证**（`powershell.exe -File start-site.ps1 -NoBrowser`）：解析零错误、0 个非 ASCII 字节；端口被占用时输出 `[STOP] ... will not switch ports` 并**不启动任何服务**；正常时打印 `URL: http://localhost:8000`，`Invoke-WebRequest` 对首页与 `/js/subtitle.js`、`/js/player.js`、`/css/style.css` 全部 **HTTP 200**，且服务出的文件含本轮 P8 内容（`fte-sub-notes-v1` / `abTick` / `Player.waveSegRange`）。

**8-4b 二次修复：浏览器永不弹出（探活用 `localhost` + 2 秒超时）**

上线后实测复现：窗口里 `Serving HTTP on 127.0.0.1 port ...` 一切正常，但浏览器始终不弹出、也没有任何报错。根因是一次真实测量出来的叠加缺陷：

- `localhost` 在本机**先解析到 IPv6 `::1`**（`[System.Net.Dns]::GetHostAddresses('localhost')` 顺序为 `::1` → `127.0.0.1`），而 python 只绑 IPv4，那一次连接要卡住后才回落到 IPv4；
- 实测单次 `Invoke-WebRequest http://localhost:8088` 耗时 **2.3s**，而 `http://127.0.0.1:8088` 只用 **1.1s**；
- 探活循环写的是 `-TimeoutSec 2` → **每一次都恰好超时** → 60 次循环跑完（约 2 分钟）后**静默退出**，服务器在跑、却什么都没有发生。

三处修正：① 探活改为**裸 TCP 连接 `127.0.0.1`**（不经 DNS / IPv6 / HTTP / 系统代理；本机装了 `127.0.0.1:10809` 的 WinHTTP 代理且 **Bypass List 为空**，走 HTTP 探活还会被代理牵进去）；② **地址栏用 `http://localhost:<port>`**（保住 origin，老用户零迁移），**探针用 IPv4 字面量**——两者分开是本轮的关键；③ **URL 在起服务器之前就先打印**，并附一句"浏览器若没自动弹出，请手动打开该 URL"——失败从此不可能不可见。

**实测**：裸 TCP 探活对 `127.0.0.1:<port>` 在第 1 次尝试即成功（**43ms**）；`localhost` 与 `127.0.0.1` 两种写法在服务器起来后都能 200（前者慢 1.2s）；与脚本同构的 `Start-Job` 内循环也已实测第 1 次尝试即连通。

**8-4c 占用者到底是谁：更正与结论**

上一版把 8000 的占用者写成"记忆核心每次都抢 8000"，**这个判断是错的**，实测更正如下：

- 「记忆核心」是本地插件 **`dsh-memory-eternal`** 的 web UI，它的端口由配置决定，而**两个配置源都写着 `7999`**：`%APPDATA%\dsh-desktop\harness\settings.yaml`（`memory-eternal.webPort: 7999`）与同目录的 `memory-eternal-config.json`（`"webPort": 7999`）。它的 `lib/web.js` 是 `server.listen(port)`，**没有回退到其它端口的逻辑**；
- 直接问服务本身即可确认身份（它只在 `/`、`/index.html`、`/app.js` 和 `/memory-eternal/api/*` 应答，其它路径一律 404）：
  `Invoke-WebRequest http://127.0.0.1:7999/memory-eternal/api/overview` → `ok=true`、`vaultDir=…\harness\memory-vault`；
- 因此 8000 上那个「记忆核心」页面是一个**历史遗留实例**（用旧端口启动的常驻 web/watchdog 子进程；插件默认 `watchdogAutoSpawn: true` 且注释写明"故意不杀"），它在本次会话中随配置重新同步而退出；
- **结论**：记忆核心的正确端口是 7999，学习站用 8000，两者本该互不干扰。实测（3 分钟 × 12 次采样）7999 全程 UP、**8000 一次都没再出现**；再以**默认参数**跑启动器 → 直接绑定 8000、无 `[STOP]`/`[WARN]`，首页与 `js/subtitle.js`、`js/player.js`、`css/style.css` 全 **HTTP 200** 且含 P8 内容，同时 7999 的记忆核心仍 `ok=true`。

**端口归属与排查（留给以后）**：

| 端口 | 归属 |
|---|---|
| **8000** | 本学习站（`http://localhost:8000`，老进度就在这个 origin 下） |
| **7999** | 记忆核心 `dsh-memory-eternal` 的 web UI 与 API |

- 若某天 8000 又被占：启动器会打印 `[STOP]` 与占用者（`Get-PortOwner`），按提示处理即可；**不要把记忆核心的 `webPort` 改回 8000**。
- 查端口归属时注意：`Get-NetTCPConnection -LocalPort 8000` 对"独占监听"的进程可能**看不到**，`netstat -ano | findstr :8000` 往往能看到 PID；最稳的判断是**自己试绑**（`TcpListener` + `Start()`，失败即被占）——启动器用的就是这一招。

**8-4d 顺带修掉启动器两处"会挂死/会误判"的写法**（都是本轮实测暴露的）：

1. **Python 误判**：`Find-PythonCmd` 原先用 `& python --version 2>&1` 判断"装了没"，而受限环境下**子进程标准输出管道会被拒绝**（实测 `& python --version` 捕获失败）→ 明明装了 Python 却打印 `[ERROR] Python not found`。现在：先排除 `\WindowsApps\` 的商店占位 stub，版本探测失败时**仍采用已解析到的命令**，把真正的 python 报错留给后面（比一句错误的"未安装"可操作得多）。
2. **窗口挂死**：Python 未找到与"服务已停止"两处的 `ReadKey` 原是**无条件**的 → 无人应答时永久挂起（本轮实测 60s+ 超时）。现在只在"确有真人控制台且非 `-NoBrowser`"时才等待按键。

**8-4e 双击打不开的真凶：`.bat` 被写成了 LF 换行 + 内含中文字节**

现象：在 PowerShell 里用 `cmd /c "启动外贸英语网站.bat" -NoBrowser` 能跑通，但**从资源管理器双击就一闪而过**。实测字节后确认两个叠加问题：

| 文件 | 当时实测 | 为什么致命 |
|---|---|---|
| `启动外贸英语网站.bat` | **CRLF=0，裸 LF=5，非 ASCII=48** | ① `cmd.exe` 解析批处理是**按 CR** 定位行边界的，LF-only 会让解析错乱；② 文件里嵌着中文文件名（非 ASCII 字节），而 cmd 用**控制台代码页**解码 BOM-less 的 .bat —— 从 PowerShell 调用时该控制台恰已是 UTF-8（所以侥幸能跑），**双击时 cmd 以 cp936 启动**，第 2 行 `chcp 65001` 又在文件中途切换代码页 → 第 5 行的中文路径解析崩掉，窗口一闪即关 |
| `启动外贸英语网站.ps1` | 裸 LF（无 CRLF） | PowerShell 能正确解析 LF，**不是**故障原因（但已顺带改名，见下） |

修法与**不变量**（以后改这两个文件必须守住）：

1. **`启动外贸英语网站.bat` 必须是「纯 ASCII + CRLF」**。为此脚本改名为 **`start-site.ps1`**（ASCII 文件名），`.bat` 里只写 `%~dp0start-site.ps1` —— 中文**目录**路径由 `%~dp0` 在运行时取得（经 `CreateProcess` 以 UTF-16 传递，与 .bat 自身字节无关），因此 .bat 内不再需要任何非 ASCII 字节，也就可以去掉 `chcp`。
2. `.bat` 现在还会：检查 `start-site.ps1` 是否存在、打印 `[launcher exited, code N]`、并**在结尾 `pause`** —— 窗口永远不会"什么都没看见就关掉"。
3. 改完必须复核字节（下面这条命令同时检查 CRLF 与非 ASCII）：
   ```powershell
   $b=[IO.File]::ReadAllBytes('启动外贸英语网站.bat'); $crlf=0;$lf=0;$na=0
   for($i=0;$i -lt $b.Length;$i++){ if($b[$i] -eq 10){ if($b[$i-1] -eq 13){$crlf++}else{$lf++} }; if($b[$i] -gt 127){$na++} }
   "CRLF=$crlf 裸LF=$lf 非ASCII=$na"   # 期望：裸LF=0、非ASCII=0
   ```
4. 复现"双击"的正确姿势（不要用默认控制台，那样会掩盖问题）：
   ```powershell
   & cmd /c 'chcp 936 >nul & "启动外贸英语网站.bat" -NoBrowser'
   ```
   **实测**：修好后在该 cp936 环境下 `.bat` 正常拉起服务，`http://localhost:8000/`、`/js/subtitle.js`、`/css/style.css` 全 **HTTP 200** 且含 P8 内容，同时 7999 的记忆核心仍 `ok=true`。
5. 注意：该 cp936 控制台里启动器打印的 `Site: E:\deepseek harness\外贸英语` 若被**重定向捕获**会显示成乱码（PS 5.1 按 cp936 写字节，读取端按 UTF-8 解），**真实控制台显示正常**，属捕获假象，不是缺陷。
