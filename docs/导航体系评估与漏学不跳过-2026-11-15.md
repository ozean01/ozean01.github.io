# 导航体系评估 + 「漏学不跳过」核实（2026-11-15）

> 对象：`E:\deepseek harness\外贸英语`（v1.33.0）
> 结论先说：**菜单乱是真的，但根因不是数量，是「同一件事有两个入口、两套名字」**；
> **漏学不会跳过单元**（代码可证），**但漏学会让到期卡悄悄积压**——这才是你真正会踩的坑。

## 一、导航体检（实测，不是观感）

现状：**一级 6 项 / 入口 18 个**（`index.html:103` 起），其中 4 个一级项是折叠组：

| 一级 | 入口 |
|---|---|
| 📅 今日 | 唯一权威入口 |
| 📚 课程 | 19 单元 |
| 练 | 听说训练（五阶段闯关·练）· 📡 口语测评（四维·自由表达）· 🤖 AI 对练（含实战关卡）· 🔤 音素·辨音·连读 |
| 记 | 记忆单词卡（FSRS）· 智能测验 · ⚠️ 高频易错点 |
| 用 | ✍️ 写作 · 🧭 实操 SOP · 🗣 说我想说 · 📥 素材（导入·逐句精听）· 🎧 真实商务听音源（泛听）· 🔍 专业术语速查 |
| 地图 | 🗺 全站地图 · 📅 计划·打卡·手册 · 📡 能力证据·口语测评（能力） |

### 1.1 三个真问题（按严重度）

**① 同一页挂了两个入口、两套名字（最严重）**
`#/speaking` 同时出现在「练 → 📡 口语测评（四维 · 自由表达）」和「地图 → 📡 能力证据 · 口语测评（能力）」，靠 `title` 属性解释"这是同一页"（`index.html:139`）。
这不是体贴，这是体系没定：**一个页面用一个功能名，而不是用"看的角度"起两个名**。用户会以为这是两个东西，点进去发现一样，于是不再相信菜单。

**② 分组轴混用：三个组按"行为"分，一个组按"元功能"分**
「练 / 记 / 用」是按学习行为分的；「地图」组里塞了三个不同性质的东西——**全站地图**（导航的导航）、**计划·打卡**（坚持度）、**能力证据**（成果）。后两个都不属于"地图"。
同时「🎧 真实商务听音源（泛听）」放在「用」组，但它和「练 → 听说训练」是**同一条听力输入链的两端**，被分到两个组里。

**③ 入口名要靠括号补丁才能自解释**
「听说训练（五阶段闯关 · 练）」「AI 对练（含实战关卡）」「全站地图（6 大区 · 目标筛选）」——**括号越多，说明入口名越没把职责说清**。而「记忆单词卡（FSRS）」这种括号又是在写实现细节（用户不需要知道算法名）。

### 1.2 建议的新结构（守住「只减不增」，入口 18 → 17）

把分组轴统一成**学习闭环**，而不是"工具类别"：

| 新一级 | 收什么 | 变动 |
|---|---|---|
| 📅 **今日** | 唯一入口（五步清单 + 到期词短文 + 明日锚点） | 不变 |
| 📚 **学** | 19 单元（含水平自测推荐位） | 不变 |
| 🎧 **输入** | 真实商务听音源（泛听）· 素材（导入·逐句精听）· 音素·辨音·连读 | 从「用」「练」各抽一个过来 |
| 🗣 **输出** | 听说训练（五阶段）· AI 对练 · 写作 · 说我想说 | 合并「练」「用」的输出侧 |
| 🔁 **记忆** | 记忆单词卡 · 智能测验 · 高频易错点 | 不变 |
| 🧭 **实战** | 实操 SOP · 专业术语速查 · 一页纸小抄 | 不变（速查类归位） |

**关键的一减**：把「📡 能力证据 · 口语测评」从导航里**删掉**，只保留「🗣 输出 → 口语测评」一个入口，能力证据作为该页内的一个视图。这样：
- 一级仍 6 项、入口 **18 → 17**（棘轮是"只减不增"，减是允许且被鼓励的）；
- 消掉"同页双入口"这个最伤信任的问题；
- 分组轴从"混合"变成"一条链"：**今日 → 学 → 输入 → 输出 → 记忆 → 实战**，用户在任何一个页面都能回答"我在链条的哪一段"。

**为什么不新增页面/入口**：一级 6 项与入口 18 个是 `test-home` / `test-ia-firstscreen` 守着的棘轮。上面这套是**重排 + 减一**，不动数字上限。

### 1.3 落地代价（诚实）

- 改 `index.html` 导航块 + `test-home` / `test-ia-firstscreen` 里的入口清单常量 + README「共 N 个入口」；
- 全站 6 处面包屑与页面头的分组名要跟着改（`app.js` 里有 `crumbs`）；
- `app.js` 现在只剩约 65 字节上限余量——**这批要动它，得先给它减负或拆文件**，这是主要成本；
- 建议：**分两批**。第一批只做「删掉重复入口 + 改分组名」（不新增路由，`app.js` 改动极小）；第二批再做「输入/输出」的入口归位。

## 二、「漏学不跳过」核实结果

### 2.1 好消息：单元不会跳过（代码可证）

- `js/today.js:513` `startUnit(units, prog)` = **取第一个未完成单元**（`unitDone` 口径），**与日期无关**；
- 今日五步清单每天重置是**清单本身的本意**（`loadDone()` 按 `todayStr()` 存，`js/today.js:43-52`），不是进度重置；
- 所以：**你停三天回来，单元还停在第 N 个，昨天没勾的步骤会重新出现**，不会"跳到下一个"。

### 2.2 坏消息：漏学会让到期卡悄悄积压，且没有任何提示

`js/flashcards.js:207-208`：
```js
enqueue(fresh.slice(0, maxNew));   // 新卡一次最多 15 张
enqueue(due.slice(0, limit));      // 到期卡一次最多 limit（默认 30）张
```
漏学一周，到期卡可能 200+ 张，但**每次会话只给 30 张**，剩下的当天不会出现，页面也不会告诉你"还欠 170 张"。用户看到的是"我明明没复习完，进度却说今天没到期了"——**这才是"跳过"的真实体感来源**：不是单元跳了，是**到期队列被静默截断**。

另外 `comeback()`（欢迎回来）只会建议"只做前两步（约 9 分钟）"，**不承接积压**。

### 2.3 建议的修法（小改动，不新增导航）

1. **把积压显式化**：今日第 1 步文案在 `due > limit` 时改成
   「到期 **X** 张，本轮先做 **30** 张（还剩 **X-30**）」——一句话把暗账变成明账（`today.js` 的 `buildSteps()` 第 1 步 `why` 字段，已有 `d.due`）。
2. **给"继续做剩余"一个出口**：会话做完 30 张后，完成页给一个「还有 N 张到期 → 再来一轮」按钮，复用既有 flash 会话（**不新增路由**）。
3. **欢迎回来时接管积压**：`comeback()` 里加一句「你还有 N 张到期卡；今天只清这一批也算数」，把"补课焦虑"变成"一个可完成的动作"。
4. **口径**：这三处都只改文案与按钮，**不动 FSRS 调度、不动单元指针**——绝不引入"按日期推进/跳过"的逻辑。
