# 5 分钟可用性测试脚本（批次 B · 2026-10-24）

> 目的：把质量证据从「自测 + 门禁」扩展到「真人验证」。目标用户：在职外贸业务员（不熟悉本站）。
> 形式：一对一面测或远程共享屏幕，全程只观察、不提示；用户原话逐字记录。
> 每个任务后问一句：「你刚才在心里想的是什么？」（捕捉心智模型）。

## 准备

- 设备：测试对象自己的电脑（他们的真实环境才是有效环境）。
- 前置状态：清空该浏览器的本站 localStorage（无痕窗口最简），保证是「第一次打开」。
- 录屏（征得同意），另备纸笔记时间戳。

## 任务 1 · 第一次打开 → 开始学习（目标 ≤ 90 秒）

**引导语**：「假设同事给你推荐了这个学外贸英语的网站。你现在打开它——请做你自然会做的事。」

| 观察点 | 成功标准 |
|---|---|
| 落地后第一眼做什么（读哪里/点哪里） | 能说出「今天该做什么」 |
| 是否找到并理解「测测起点」 | 主动点「🎯 测测起点」或「今日」清单 |
| 五步清单是否被理解为「按顺序做」 | 能复述至少 3 步 |

**红旗**：去点「首页」逛全站地图超过 30 秒；问「这是干嘛的」超过一次；点导航逐个展开组。

## 任务 2 · 客户来电 → 场景急救（目标 ≤ 2 分钟）

**引导语**：「想象客户五分钟后要来电话，谈压价。你现在必须马上能说出几句英文。」

| 观察点 | 成功标准 |
|---|---|
| 是否找到「🚨 场景急救」 | ≤ 2 次点击内到达 |
| 三句能说出口的话是否被使用（朗读/复制） | 至少朗读一次 |
| 是否发现出口（送 AI 对练 / 关联单元） | 能说出「接下来能去哪练」 |

**红旗**：先去导航逐组找「口语」；没注意到场景 chips 需要滚动；把「场景急救」当成课程点进单元。

## 任务 3 · 投料 i+1 挖掘 → 只练该练的（目标 ≤ 2 分钟）

**引导语**：「这是客户邮件里的一段英文（粘贴 4 句测试材料）。网站刚加了新功能，你试试让它帮你挑出最值得练的句子。」
（测试材料 = `tools/test-esp-mine.js` 里那 4 句；预置该用户的「已掌握词」状态。）

| 观察点 | 成功标准 |
|---|---|
| 是否注意到 i+1 徽章与摘要 | 能说出「哪些句子是 i+1」 |
| 「只送 i+1 句」开关是否被理解 | 开启后能说出送出去几句 |
| 口径注释是否被读到 | 能转述「词库外的词不算生词」 |

**红旗**：忽略徽章直接全量送入；认为「生词」应包含词库外普通词并困惑（→ 记录：口径文案需要更醒目）。

## 记录模板（每个用户一份）

```
用户编号 / 日期 / 设备与浏览器：
任务 1：完成 □ 失败 □  用时 ___s  卡点：
任务 2：完成 □ 失败 □  用时 ___s  卡点：
任务 3：完成 □ 失败 □  用时 ___s  卡点：
原话引用（逐字）：
最意外的一个发现：
```

## 汇总规则

- 3 名用户同一卡点重复出现 → 列为 top3 修复项（小批次修复 → 复测同一任务）。
- 单人偶发问题记入「已知取舍（诚实清单）」候选，不立即修。
- 完成率目标：任务 1 ≥ 3/3，任务 2 ≥ 2/3，任务 3 ≥ 2/3；不达标即本批未通过。

## 反馈通道（无后端）
